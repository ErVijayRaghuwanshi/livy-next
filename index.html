Why Livy-Next

The Evolution to Apache Spark 4.x

Legacy Apache Livy served Spark 2.x and 3.x reliably for years. However, beyond Spark 3.5, official Apache Livy maintenance has halted with no native support for Spark 4.x. As modern data architectures transition to high-speed gRPC and Spark Connect, Livy-Next provides the natural cloud-native evolution.

Spark 2.x – 3.5 Era

Traditional Apache Livy

A dependable pioneer for interactive Spark execution throughout the Spark 2.x and 3.x lifecycle. However, for modern Spark 4.x deployments, it encounters practical architectural constraints:

  • ⚠️
    20 to 600s Session Cold-Start Delay: Spawns an isolated, full Spark application and separate JVM driver for every single session. Users wait 20 to 600+ seconds for YARN resource allocation and driver startup.
  • ⚠️
    Resource Hoarding (No Shared Multi-Tenancy): Each idle session hoards dedicated YARN memory and CPU cores, blocking other users and inflating cloud cluster costs.
  • ⚠️
    No Official Support Post-Spark 3.5: Upstream Apache Livy development has stalled, leaving no official releases or roadmap for Apache Spark 4.x.
  • ⚠️
    Lacks Modern gRPC (Spark Connect): Designed around process-forked drivers and legacy spark-submit rather than the decoupled sc:// gRPC protocol.
  • ⚠️
    Gateway JVM Overhead: Requires a local Java/Scala runtime and heavyweight JVM dependencies (1–2 GB heap) directly on the gateway host.
Spark 4.x & Beyond

Livy-Next Gateway

A high-performance cloud-native gateway written in Go. Keeps all existing Livy REST client workflows while natively leveraging modern Spark Connect gRPC:

  • ✅
    Instant Multi-Tenant Sessions (< 1ms): All sessions multiplex over a single, shared Spark Connect Server application. Creating a new session takes under 1ms with zero YARN allocation queue time or driver cold starts.
  • ✅
    True Multi-Tenant Cluster Efficiency: Multiple users, notebooks, and pipelines share cluster resources dynamically without spinning up wasteful isolated Spark applications.
  • ✅
    Native Spark Connect (gRPC): Communicates directly with Spark 4.x drivers via sc:// channels and Apache Arrow columnar memory transport.
  • ✅
    100% Drop-In REST Preservation: Keeps existing Livy endpoints intact so notebooks, Airflow, and Livy-UI run seamlessly without changes.
  • ✅
    Zero Local JVM: Single statically compiled Go binary (< 40MB) using only ~15–30 MB RSS memory. Instant container boot with zero JVM dependencies.

Instant Multi-Tenant Sessions

Auto-Reaping · Zero Leaks

Getting Started

Up and Running in 60 Seconds

Deploy via Docker, compile with Go, or integrate directly with Apache Airflow.

# 1. Clone Livy-UI (React 19 + Vite 7 + Tailwind CSS 4 + Monaco Editor)
git clone https://ervijayraghuwanshi.github.io/livy-ui.git
cd livy-ui

# 2. Install dependencies & start web app
npm install
npm run dev

# 3. Open http://localhost:5173 and connect to Livy-Next at http://localhost:8998
# Native CORS support is handled directly by livy-next (--cors-allowed-origins "*")
⭐ Includes Monaco Editor, 300+ Spark SQL autocomplete keywords, schema tree, EXPLAIN plan viewer & PWA. View Livy-UI GitHub Repo → 
# Run Livy-Next connected to a remote Spark 4.x Connect cluster
docker run -d \
  --name livy-next \
  -p 8998:8998 \
  -e SPARK_REMOTE="sc://spark-master:15002" \
  -e IDLE_TIMEOUT="30m" \
  ghcr.io/ervijayraghuwanshi/livy-next:v1.0.0

# Verify the service is online
curl http://localhost:8998/version
# Clone repository and compile binary
git clone https://github.com/ErVijayRaghuwanshi/livy-next.git
cd livy-next

# Download dependencies and build binary
make tidy
make build

# Start the gateway pointing to Spark Connect
./bin/livy-next --addr :8998 --spark-remote sc://localhost:15002 --cors-allowed-origins "*"
from airflow import DAG
from airflow.providers.apache.livy.operators.livy import LivyOperator
from datetime import datetime

with DAG(
    dag_id="spark_connect_pipeline",
    start_date=datetime(2026, 1, 1),
    schedule="@daily",
    catchup=False,
) as dag:
    # Drop-in compatible with standard Airflow LivyOperator!
    run_spark_query = LivyOperator(
        task_id="aggregate_sales",
        livy_conn_id="livy_next_default",  # Pointed to http://livy-next:8998
        file="spark_job.py",
        conf={"spark.sql.shuffle.partitions": "16"},
    )
# 1. Create a new interactive session
curl -X POST http://localhost:8998/sessions \
  -H "Content-Type: application/json" \
  -d '{"kind": "spark", "name": "analytics-session"}'

# 2. Submit SQL statement
curl -X POST http://localhost:8998/sessions/0/statements \
  -H "Content-Type: application/json" \
  -d '{"code": "SELECT current_timestamp(), count(*) FROM delta.`/data/events`"}'

# 3. Poll statement results
curl http://localhost:8998/sessions/0/statements/0

Description

Queries both the Livy-Next gateway release version and the underlying Apache Spark Connect cluster runtime details probed dynamically on startup.

Description

Triggers graceful session teardown. Sends a `ReleaseSession` RPC to the remote Spark Connect server and cleans up internal registry state.

  "msg": "deleted"

CLI Flags & Options

Runtime Configuration

Fine-tune networking, keep-alives, timeouts, and cluster parameters.

Showing all production flags for v1.0.0
CLI Flag Default Description
--addr :8998 Host address and port the Livy-Next HTTP gateway binds to.
--spark-remote sc://localhost:15002 Connection string for the remote Spark Connect gRPC server.
--spark-ui-url http://localhost:4141 Base URL for the Spark Web UI (deep-linked from sessions).
--spark-history-url http://localhost:18088 Base URL for the Spark History Server UI.
--spark-token "" Pre-shared authentication bearer token for Spark Connect.
--idle-timeout 30m Duration after which inactive running sessions are automatically reaped.
--sync-session-timeout true Dynamically inherit session timeout from Spark Connect server.
--dead-timeout 5m Duration after which dead/stopped sessions are removed from memory.
--default-statement-limit 10000 Default maximum rows returned by SQL queries (0 for unlimited).
--grpc-keepalive-time 60s gRPC keepalive ping frequency for Spark Connect channels.
--grpc-keepalive-timeout 20s gRPC keepalive ping timeout duration before reconnection.
--cors-allowed-origins * Comma-separated list of allowed CORS origins for browser security.
--mock false Enables in-memory mock Spark client for offline CI/CD verification.
